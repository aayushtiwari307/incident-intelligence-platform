# 0008 Testing conventions

- Unit tests (`*.test.ts`) should not need external services.
- Integration tests (`*.int.test.ts`) use PostgreSQL and fail, never silently skip, when `TEST_DATABASE_URL` is missing. The actual runtime adapter matters: a database test through a `psql`-backed adapter is not proof that the `pg` pool wrapper works.
- Each integration test creates its own uniquely named scratch database, so tests do not interfere with the service database. The supplied test connection must have `CREATEDB` privileges.
- A test guarding a bug should be mutation-checked when feasible; reintroducing the bug must make the test fail.
- Tests are not weakened just to obtain a green result. A wrong expectation may be corrected only after identifying the reason.
- Property-based tests are planned for state-machine and permission invariants as the platform grows.
- Reports must name the runner and distinguish actual framework/runtime tests from test harnesses or stand-ins.
