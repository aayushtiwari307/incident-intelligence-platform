# Change-event webhook

The M10 implementation accepts deploy/change events through `POST /api/v1/integrations/changes`. The integration credential is generated by the existing integration management flow with kind `change-events`; only the hash is stored. Create/manage this credential as an organization owner/admin, and copy the returned secret once into your deployment or CI secret store. The plaintext credential is never returned again or written into this repository.

## Payload

```json
{
  "service": "payments-api",
  "source": "ci-deploy",
  "externalId": "deploy-2026-10-24-001",
  "version": "release-2026.10.24.1",
  "actor": "release-bot",
  "timestamp": "2026-10-24T12:00:00.000Z"
}
```

All fields are validated and bounded. `timestamp` must be within the last 30 days and not more than five minutes in the future. An integration may only reference a service in its own organization. The source + external ID is idempotent within that organization; retrying the same key returns the accepted event ID without duplicating the change.

Send an `Authorization: Bearer <integration-token>` header over HTTPS. Do not put the token in the URL or JSON body. The request accepts one event object per delivery (not a batch); the request body is read only after the credential is checked and is capped by `WEBHOOK_BODY_LIMIT_BYTES`. Requests are rate-limited in memory per API process; multi-instance deployments multiply the effective limit and would need a shared limiter to obtain a global cap.

## Correlation and event fan-out

For an incident with a linked service, the incident page lists matching events within the 24 hours before the incident's `created_at`, latest first. It explicitly labels each row `correlation, not proven cause`. Other tenants, other services, future changes, and older changes are excluded. New changes create small `incident_events` wake-up rows for a bounded number of nearby incidents, which reuses the existing PostgreSQL `LISTEN/NOTIFY` realtime path when realtime is enabled.

## Local simulator

Use a disposable local API and a test-only integration credential. The simulator refuses non-loopback URLs by default and prints no token:

```cmd
set "IIP_CHANGE_SIMULATOR_URL=http://127.0.0.1:3001/api/v1/integrations/changes"
set "IIP_CHANGE_TOKEN=PASTE_TEST_ONLY_TOKEN_HERE"
set "IIP_CHANGE_SERVICE=payments-api"
npm run simulate:change
```

Do not use production credentials against the simulator. The integration tests use mocked/request-local seams and must target only a disposable loopback PostgreSQL database.
